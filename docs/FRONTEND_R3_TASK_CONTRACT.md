### R3-2 工作台四层优先级（用户 2026-10-14 强化）

第一层：当前用户最值得完成的 **1 项任务**；第二层：最多 **3 项**高优先级待办；第三层：当前经营阶段 + 需关注阻断 + 真实经营摘要；第四层：按需展开的 AI 执行历史 + 完整经营数据。已有订单卖家 vs 无店铺新手呈现**不同任务入口**（确定性画像规则，不靠 LLM）。

### R3-3 页面必须围绕对象与任务设计

优先重构：我的生意 / 我的商品 / 商品详情 / 新手选品 / 货源比选 / 成本试算 / 商品上线 / 任务与审批。每页必须明确：**当前对象、当前目标、关键数据、唯一主要动作、下一步、错误处理、返回路径**。专业能力可访问，但不要求新手理解内部术语即可完成任务。
J0 的市场需求、供应报价、经营收益必须区分**真实/估算/未知**，不得用演示数据冒充真实商机。

## 3. J0–J4 旅程契约（任务驱动）

### J0 零基础纵向旅程（最高优先级）

新手从空白进入：

```
登录 → 新手引导(/onboarding) → 我的生意(/app)
  → "今天需要你处理"（1–3 项，非 6 屏堆叠）
  → 已有商品 or 选品起步
  → 连接店铺（渠道 OAuth，连店成功≠全操作可用）
  → 补资料（素材/合规缺口）
  → 启动上线（J1）
  → 完成当前人工事项
```

**验收**：不口头指导下，30 秒内从首页找到"当前最优先任务"；关键步骤不需要理解 Listing/工作流模板等内部概念。

### J1 商品上线主旅程

```
商品库(/app/products) → 商品详情(/app/products/:id)
  → 准备度/货源/成本/渠道状态（主档事实 + 渠道按店独立进度）
  → 继续上线(/app/launch/:id) → 当前步骤所需材料
  → 缺资料补材料 → 回到原步骤 → 继续
  → 等待平台 / 人工完成 → 结果回执（什么改变了/仍缺什么/下一步）
```

**验收**：双店独立进度不混为一条记录；冲突先刷新合法动作、保留用户输入；失败重试不复用失效 revision。

### J2 待办闭环

```
我的待办(/app/tasks) → 对象证据（直达具体对象/动作，≤2 次导航）
  → 人工决定/审批 → 结果 → 待办更新（去重，来源追溯）
```

**验收**：相同业务事项只展示一次；401/403/409/超时/部分数据均有可理解反馈；刷新返回不丢关键上下文。

### J3 经营异常追溯

```
在售商品 → 经营异常（/app/risk/alerts 或 BI）
  → 利润依据（成本/费用/退款/广告来源，币种周期标注）
  → 提出动作（AI 建议/定价/采购）
  → 执行回执
```

**验收**：不同币种不直接相加；缺失数值不当零；估算标 ESTIMATED。

### J4 订单异常闭环

```
订单异常(/app/orders) → 采购/备货/履约(/app/fulfillment)
  → 处理结果 → 售后/结算关联(/app/refunds、/app/settlements)
```

**验收**：未知物流不伪造轨迹；备货与销售订单不混为一谈；关联不用多个 ID 手工搜索。

## 4. 数据可信度渲染契约（四轴分离）

| 轴 | 取值 | 渲染规则 |
|---|---|---|
| 页面加载状态 | LOADING/ERROR/READY | SectionState 11 态，文案不页面自写 |
| 业务流程状态 | draft/in_progress/blocked/done | BusinessStatus，不单靠颜色 |
| 外部平台状态 | SUBMITTED/ACTIVE/VERIFIED | 提交≠在售，明示 |
| 数据可信度 | VERIFIED/OBSERVED/ESTIMATED/MISSING/DEMO | 8 类数据标签 |

**禁止项**（0 容忍）：错误当空、未知当零、提交当在售、建议当执行、未授权当已接入。金额带币种，百分比带分母与周期，未知用「—/尚未获得」。

## 5. 任务契约 Read Model 与 allowed_actions

- 每个业务对象（商品/上线/订单/待办）页面消费**稳定 ViewModel**，不散落猜测 `items/data/channels`。
- `allowed_actions` 由后端返回，前端按动作渲染权限（修 E10 通用 canWrite）；403 不显示为空，409 保留输入。
- API 域适配层（`api/domains/*.js`）使用真实响应样本做契约测试。
- 跨页上下文包含 `product/shop/run/step/return_to` 适用部分；`return_to` 仅允许站内合法路径，服务端重新验证。

## 7. 角色隔离契约（6 角色）

| 角色 | 数据范围 | 必须隔离 |
|---|---|---|
| OWNER | 全空间 | 代客身份持续可见 |
| OPERATOR | 授权店铺 | 不越权写 |
| READ_ONLY | 授权店铺只读 | 写操作不可见 |
| COMPLIANCE | 授权合规材料 | 通用写权≠专属审核 |
| FACTORY_COLLABORATOR | 本厂供给 | 不暴露销售利润/全店数据 |
| PLATFORM_ADMIN | 平台控制台 | 与商家导航隔离，退出代客恢复原身份 |

跨空间/店铺数据不泄露；Workspace 切换取消旧请求并清理缓存/所选店铺/批量选择。

## 8. 验收门槛（R3-5 前冻结）

| 维度 | 门槛 |
|---|---|
| 能找到 | ≥3 名未参与实现用户，首页 30 秒内找到待处理上线流程 |
| 能完成 | J1/J2 本地可控部分完成率目标 ≥90%（外部等待计准确进入等待态） |
| 少绕路 | 商品→店铺 Launch、待办→对象均 ≤2 次导航 |
| 不丢功能 | 旧功能逐项记录复用/迁移/合并/暂缓原因 |
| 不误导 | 0 个核心路径违反 §4 禁止项 |
| 异常可恢复 | 401/403/409/422/超时/部分数据/撤权/重复点击均可理解 |
| 工程 | 受影响组件交互测试 + 真实响应契约测试 + 隔离 E2E + 回归/构建通过，不降断言 |
| 部署 | 验收产物与正式入口 build 身份一致；深链刷新可用；回退演练不改业务事实 |

**不以文件存在、页面数、纯函数测试代替页面操作可用证据。** 浏览器操作/截图/网络证据必须来自实际页面。
