# AI 跨境电商 ERP 业务 UI 与流程整改蓝图

## 目标

让前端严格表达后端的真实能力和业务状态，围绕“机会发现 → 私域/1688 供给 → 收益门禁 → 合规与审批 → 平台发布 → 订单履约 → 售后结算 → 经营复盘”完成可追溯闭环。

## 约束与真实性标签

- `demo/local` 只能用于演示，不能显示为真实同步、真实发布或真实营收。
- `protocol_ready_unverified` 只代表协议实现，未经官方开发店或真实店铺验收不得标记生产可用。
- 所有金额决策统一使用财务服务的记账币种口径；缺汇率、费用或结算数据必须显式降级可信度。
- 外部平台异步操作必须区分 `submitted / processing / published / failed / uncertain`。
- 自动化不得绕过工厂尽调、预测商用门禁、ListingReviewAgent 或人工审批要求。

## 角色与工作区

| 角色 | 核心任务 | 前端能力边界 |
|---|---|---|
| admin | 配置、用户、店铺、规则、最终管理 | 全租户管理，不得审批自己提交的 Listing |
| operator | 选品、商品、订单、采购、客服 | 不得修改系统设置或执行合规审批 |
| compliance_approver | 处理上架复核待办 | 只显示复核证据、规则版本、批准/驳回 |
| viewer | 只读经营分析 | 隐藏全部写操作 |
| supplier | 维护本厂商品、价格、产能 | 只能访问工厂门户及本厂数据 |
| superadmin | SaaS租户与平台运维 | 与租户工作台隔离，代客访问有明确进入/退出状态 |

## 后端能力与前端承接

- 店铺与平台：店铺页承接 OAuth、真实拉单、规则版本、类目映射；Listing 页承接上架准备检查和异步提交状态。
- 财务：独立财务工作台承接 FX、订单行/费用、平台结算导入和差异处理。
- 工作流：运行历史展示步骤、检查点、阻断原因，并允许对 `failed/blocked/partial` 安全恢复。
- 供应链：供应商页展示工厂尽调、目录新鲜度、机会历史、收益门禁和报价转化。
- 权限：系统设置新增租户用户、角色、停用和凭证撤销入口。
- BI：Dashboard、BI和AI报告统一调用同一指标服务，不再直接汇总旧 `Order.profit`。

## 导航与任务流

1. 概览：可信经营指标、数据缺口、待处理任务、异常。
2. 机会中心：趋势、商品机会、私域工厂匹配、收益门禁。
3. 上架中心：草稿、复核待办、人工审批、平台提交、最终状态。
4. 订单履约：按真实店铺同步、异常订单、发货、代发关联。
5. 财务中心：汇率、订单费用、结算对账、可信度。
6. 自动化中心：模板、调度、运行检查点、恢复与幂等状态。
7. 系统管理：用户角色、店铺、规则和数据来源。

## 页面质量要求

每个关键页面必须回答：当前状态、数据来源、需要谁处理、下一步动作、动作后的结果、失败如何恢复。列表必须具备加载、空态、持久错误态和重试；写按钮必须按角色能力隐藏或禁用；真实与演示操作使用不同视觉层级。

## 验收路径

1. admin 创建 operator、合规审批员和工厂账号。
2. 工厂维护目录，运营扫描机会并通过收益门禁。
3. 生成 Listing，提交人无法自审，审批员完成复核。
4. 选择已授权真实店铺发布，异步平台等待最终态。
5. 按店铺游标拉单并 upsert 状态、订单行和费用。
6. 完成发货/代发、退款、结算对账。
7. Dashboard、BI、AI报告和导出指标一致。
8. 工作流在网络超时和人工阻断后从检查点恢复，不重复副作用。

## 回滚边界

- 前端页面按路由独立回滚；不删除旧接口。
- 数据库只用向前 Alembic 迁移；生产回滚依赖迁移前备份及补偿迁移。
- 平台真实操作保留幂等日志与不确定态，不通过重试覆盖原始证据。
