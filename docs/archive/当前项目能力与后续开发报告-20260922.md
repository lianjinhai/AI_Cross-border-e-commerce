# AI 跨境电商 ERP 当前能力与后续开发报告

版本：2026-09-22

## 一、执行结论

当前项目已经不是单纯原型，而是一套可以本地运行、完整演示主要业务闭环，并具备真实平台协议适配基础的跨境电商 ERP。系统围绕“1688/私域工厂作为货源，海外平台作为销售市场”实现了商品、供应商、机会、定价、合规、上架审批、发布、订单、采购、售后、结算、BI、预测和多 Agent 工作流。

当前最准确的成熟度判断是：

- 本地业务闭环：可运行。
- 演示环境：可完整展示和测试。
- 导入/API 真实数据分析：已具备基础商用能力和数据门禁。
- 平台协议：TikTok、eBay、Walmart、Lazada 已实现协议链路，Shopee 已部分接通。
- 官方平台环境：仍待 Sandbox、Development Shop 或真实店铺验收。
- 无人值守大规模商用：尚未达到，主要缺口在真实平台验收、独立任务基础设施、生产运维、浏览器端到端测试和真实历史数据回测。

## 三、当前可以实际完成的业务

### 1. 账号、租户和权限

- 管理员、运营、只读、合规审批员、工厂账号、超级管理员等角色工作区。
- 租户用户创建、停用、角色调整、密码重置和 Token 撤销。
- 超级管理员租户管理与代客访问审计。
- 前后端权限同时控制；普通租户账号不能直接进入平台管理，运营和只读角色不能直达系统设置。
- OAuth state 一次性消费、过期检查、凭证加密存储、登录失败锁定和跨租户隔离。

### 2. 商品和货源采集

- 手工建品、商品更新、CSV 导入导出。
- URL 商品采集，包含结构化数据解析、SSRF 防护和验证码页识别。
- 1688 官方接口签名和采集链路；不可用时有受控降级路径。
- 商品去重指纹、标准化属性、类目和来源标记。
- 1688 被严格定义为货源端，不会作为销售平台使用。

### 3. 私域源头工厂网络

- 用户可以录入认识的源头工厂并保存来源证据。
- 工厂完成候选、接洽、尽调通过、拒绝、暂停等状态管理。
- 工厂账号只能维护本厂目录，包括工厂 SKU、价格、币种、MOQ、交期、库存、月产能、图片和能力标签。
- 系统根据市场商品、工厂能力、数据新鲜度、库存、产能和经济性生成可解释匹配。
- 只有已尽调、数据完整且明确推进的机会才能转为供应商报价并认领后续营收。
- 已建立机会到 Listing、真实订单、GMV、净收入、贡献利润和平台结算的归因链路。

### 4. 市场发现和选品

- 趋势扫描、关键词扩展和市场机会录入。
- 从需求、竞争、利润和风险维度计算商品机会分。
- 支持手动执行和定时调度。
- 机会可继续进入货源匹配、定价、合规和 Listing 流程。

目前趋势数据可以来自演示或外部导入，但尚未形成覆盖多个主流市场的稳定商业数据采购层，因此“发现结果”当前更适合辅助决策，不能直接替代运营判断。

### 5. 定价和单位经济性

- 采购价、物流、平台佣金、广告成本等综合定价。
- 供应商外币报价按可追溯汇率换算到统一口径。
- 缺少汇率时失败关闭，不会静默混算。
- 工厂机会在利润率和贡献利润不足时不能自动进入后续自动化。

### 6. 合规和上架复核

- 标题、描述、违禁宣称、品牌侵权、禁售类目、图片要求等规则检查。
- 保存规则版本、风险等级、证据和检查结果。
- Listing 经过提交、Agent 复核、人工审批、驳回或修改重提。
- 提交人不能审批自己的 Listing。
- 高风险内容不可通过普通人工操作绕过。
- 发布前再次验证合规报告、平台字段和类目映射。

需要注意：平台规则支持签名远程规则源和版本防降级，但并没有自动接入所有平台官方实时规则订阅。未配置可信规则源时使用内置规则快照，因此仍需运营和合规人员维护。

### 7. 平台店铺与发布

| 平台 | 已实现 | 当前真实状态 |
|---|---|---|
| 1688 | OAuth、采集、报价、代发下单幂等 | 货源协议部分实现，真实代发待账号验收 |
| Shopee | OAuth、Token 刷新、订单、图片及商品发布基础链路 | `partial`，优先完成 SG 实店验收 |
| TikTok Shop | 签名、Token、分页订单、图片、Global Product 创建与发布、断点恢复 | `protocol_ready_unverified` |
| eBay | OAuth、分页订单、Inventory Item、Offer、Publish Offer | `protocol_ready_unverified` |
| Walmart | OAuth、订单游标、Feed 提交、Feed 状态反查 | `protocol_ready_unverified` |
| Lazada | 授权签名、分页订单、商品创建 | `protocol_ready_unverified` |
| Amazon | 能力明确禁用 | `planned`，未冒充已接入 |
| AliExpress、Shopify、Mercado Libre | 能力矩阵与规划位 | `planned` |
| Temu、SHEIN | 受平台招商和应用审核限制 | `restricted` |

发布已使用持久化任务，绑定目标店铺，记录请求人、载荷、检查点、开始结束时间及 `queued/processing/succeeded/failed/uncertain` 状态。平台成功但本地响应中断时，可以利用已有平台资源 ID 恢复，而不是盲目创建第二份商品。

### 8. 订单、履约、采购和售后

- 按真实店铺分页拉单并幂等更新既有订单。
- 区分演示、CSV 导入和平台 API 数据。
- 订单行、费用、国家、币种、店铺和平台信息可追踪。
- 已付款订单发货和物流单号记录。
- 采购预警、最优报价选择、采购单创建、提交、收货和结算。
- 1688 代发关联销售订单、货源店铺、平台交易号和持久化幂等键。
- 退款支持审核、同意、退货、退款、拒绝及库存回补。
- 状态流转受到约束，不允许随意跨状态跳转。

### 9. 财务和经营分析

- 日级汇率、订单行、订单费用和平台结算维护。
- 统一 GMV、净收入、贡献利润、广告 ROAS/ROI 和退款率口径。
- 按交易日期选择最近有效汇率并统一到 USD 分析口径。
- 修复退款重复扣减；缺汇率、缺费用或缺结算时显示可信度问题。
- 平台结算按平台和外部结算号幂等录入，并计算应结、实结和差异。
- Dashboard、BI 和 AI 报告共用同一指标服务，避免各页面口径不同。

### 10. 预测和商用门禁

- 使用真实 API 或导入订单训练，排除演示数据。
- 支持 SKU、平台和国家维度。
- 纳入促销、缺货、价格等商品属性信号。
- 比较 last-week、12 周均值、间歇需求和加权移动平均基线，按同一时间窗的 WAPE 和 Bias 自动选择。
- 保存模型版本、训练截止时间、目标窗、预测值、置信区间和输入特征快照。
- 预测目标窗到期后自动计算真实销量、WAPE、Bias 和覆盖情况。
- 真实历史数据不足或整体预测监控不过门槛时禁止自动采购。

这已经具备可追溯预测产品的基础，但模型仍属于统计基线层，尚未达到复杂促销、节假日、价格弹性和多层级协同预测的成熟水平。

### 11. Agent 协同和自动化

已实现发现、供应商、工厂机会、定价、合规、Listing、Listing 复核、客服、总调度等专业 Agent，并通过工作流模板串联。

工作流当前支持：

- 步骤上下文传递和输出留痕。
- 技术失败、业务阻断、部分成功和成功状态区分。
- 失败恢复并跳过已经成功的步骤。
- 发布和代发幂等。
- 数据库租约、Worker 标识和长步骤心跳。
- 服务重启后恢复过期运行。
- 人工审批阻断后继续执行。

但执行器仍主要依赖应用进程内线程，不是独立队列 Worker；尚缺成熟的取消、补偿、死信队列、优先级、并发配额和跨节点调度。

## 四、当前可演示的完整流程

目前可以在本地完整演示以下闭环：

1. 管理员创建运营、审批和工厂账号。
2. 录入 1688 商品或私域工厂。
3. 工厂维护价格、库存、产能和交期。
4. 扫描市场机会并选择候选商品。
5. 匹配工厂/供应商，计算售价、利润和商业门禁。
6. 生成多语言 Listing。
7. ListingReviewAgent 检查平台规则和内容风险。
8. 独立审批人批准或驳回。
9. 选择目标店铺提交发布；无真实账号时停留在协议/本地契约状态。
10. 拉取或导入订单，执行发货、代发、退款和结算。
11. BI 计算收入、利润、退款和广告表现。
12. 预测到期后比较实际销量，并把工厂机会归因到实际经营结果。

## 五、当前不能宣称已经完成的能力

以下事项仍不能标记为生产可用：

1. Shopee、TikTok、eBay、Walmart、Lazada 官方环境的最终验收。
2. 真实 1688 代发订单在超时后的官方查单恢复证明。
3. 主流平台规则自动实时更新；目前需要可信规则源或人工维护。
4. Playwright 浏览器真实点击流；当前前端测试主要覆盖角色路由与权限逻辑。
5. PostgreSQL 高并发、锁竞争、备份恢复和大数据量压测。
6. Redis/消息队列/独立 Worker 和多实例任务调度。
7. 生产级可观测性，包括结构化日志、指标、分布式追踪和告警。
8. 真实历史订单达到统计要求后的正式预测商用认证。
9. 平台订单级结算明细不足时，目前实际到账按周期 GMV 比例分摊，仍弱于订单级精确归因。
10. 图片和知识产权合规仍以规则为主，尚未接入成熟的多模态检测和商标数据库。

## 六、主要结构性风险

### P0：上线前必须解决

- 官方平台账号和测试店验收未完成。
- SQLite 与进程内线程不适合多实例、高并发和无人值守生产。
- 缺少完整的生产备份恢复演练、监控告警和故障值守机制。
- 平台规则实时性不能仅依赖代码内置快照。

### P1：小规模试运行前完成

- 引入真正的浏览器 E2E，覆盖登录、工厂更新、机会推进、审批、发布、订单、退款、结算和工作流恢复。
- 建立官方平台验收证据表和前端验收台，而不仅是文档记录。
- 对平台 Webhook、Token 轮换、重复回调和乱序事件做专项验证。
- 将工作流执行迁移到数据库队列或 Redis/Celery/RQ 类独立 Worker。
- 对统一财务指标做数据库级聚合和索引优化。

### P2：规模化与竞争力建设

- 扩展 AliExpress、Shopify、Mercado Libre；Temu、SHEIN 等待资质后再接。
- 接入稳定的市场趋势、广告、关键词和竞品数据源。
- 增加多层级预测、价格弹性、节假日特征和库存优化。
- 建立规则订阅、变更影响分析和自动化合规回归。
- 把工厂绩效反馈回供应商评分、预测和自动选品。

## 七、建议的后续开发方向

### 第一阶段：真实平台小闭环

目标不是同时铺开所有平台，而是先获得一个可收费、可复现的真实闭环。

建议顺序：

1. Shopee SG 完成授权、发布、订单、履约和退款验收。
2. TikTok 跨境 Development Shop 完成 Global Product、订单和退款闭环。
3. eBay Sandbox 完成 Inventory Item、Offer、Publish 和订单闭环。
4. Walmart 动态 Sandbox 完成商品、订单、履约、签收和 Feed 部分失败恢复。
5. Lazada 选择一个明确国家站点完成类目 Schema 和商品闭环。

每个平台必须形成机器可读验收记录，只有证据齐全才从 `protocol_ready_unverified` 晋升。

### 第二阶段：生产基础设施

- PostgreSQL 替代生产 SQLite。
- 独立 Worker 和可靠任务队列替代进程内线程。
- Redis 用于限流、分布式锁和短期缓存。
- 增加 OpenTelemetry、结构化日志、错误聚合和业务告警。
- 完成备份、恢复、灰度和回滚演练。
- 引入 Playwright 端到端测试并进入 CI。

### 第三阶段：真实数据商用验证

- 导入至少一个真实店铺的历史订单、费用、退款、广告和结算。
- 完成时间切分回测，按 SKU/平台/国家监控 WAPE、Bias 和覆盖率。
- 财务人员核对 GMV、净收入、贡献利润与平台账单。
- 只有达到数据量、误差和对账门槛的租户才打开自动采购、自动定价和自动上架。

### 第四阶段：产品差异化

- 将“私域工厂网络 + 市场机会 + 自动上架 + 实际利润归因”做成核心产品，而不仅是通用 ERP。
- 建立工厂协同门户、询价、打样、质检、产能预约和履约评分。
- 让 Agent 从实际销售和售后结果中更新工厂选择、定价和机会评分。
- 引入市场数据供应商，形成泉州、石狮产业带的区域商品机会图谱。

## 八、推荐的产品定位

短期不建议把产品定位成“全平台全自动 ERP”。更可信且更具差异化的定位是：

> 面向拥有中国源头工厂资源的跨境卖家，用 AI 把市场机会、工厂供给、合规上架、订单履约和实际利润连接起来的经营系统。

这一定位与现有实现最吻合，也能避开与成熟传统 ERP 在仓储、财税和全平台覆盖上的正面竞争。

## 九、下一批建议执行清单

推荐立即执行：

1. 建立平台验收证据模型、API 和前端验收台。
2. 引入 Playwright，完成本地契约沙箱的浏览器级黄金路径。
3. 选择 Shopee SG 或 TikTok Development Shop 作为第一个真实闭环。
4. 设计 PostgreSQL、Redis、Worker 的生产部署方案并进行故障恢复演练。
5. 用一批真实历史订单完成首次预测和财务对账验收。

完成上述五项后，项目才能从“功能完整、协议就绪”进入“可控的小规模生产试运行”。
