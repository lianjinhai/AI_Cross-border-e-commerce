## 一、使用前明确的设计判断

这次不是简单换主题：原型要求五个主入口、以商品与店铺为中心的任务链，以及可解释的事实、缺口、主动作。当前代码已有业务能力，应重组现有页面，不再开发一套独立演示 ERP。

三个容易误映射的地方：

1. 图 04 是“商家有工厂/商品资源”的经营研究场景，不意味着外部 FACTORY_COLLABORATOR 获得商家工作台权限。
2. 图 09 是商品费用试算与风险判断，主要承接到定价/成本能力；不是把财务事实工作台改成估算器。
3. 图 06 是商品详情，素材包没有提供完整商品列表原型。列表需要沿用同一视觉体系做增量设计，标为推导设计，不能声称逐像素还原。

附带 README 是参考材料，其中关于历史测试、已交付能力的说法没有在本轮重新验证；不能自动转成运行验收结论。提示词中的页面方案是后续开发依据，不代表相应接口已经存在。

### E. 先修正确性，再完成外观

复核并优先修复下列已在静态审查发现的问题，已修复则补验证，不重复重写：

1. `Products.vue` 的类目通过 `source` 传入 `fetchProducts`，后端读取 `category`；修正真实筛选链路。

原型 README 的 BusinessGoalCard、EvidenceBadge 等是职责建议，不是要求新建同名组件。只在现有组件确实不能承接时抽取新组件；不要造两套状态字典、任务卡或审批系统。

当前 `frontend-v9/src/shared/dataLabels.js` 已有八类来源标签。原型的“已验证/填报/观察/AI估算/缺失/演示”应建立显式映射，保留来源、核验状态、完整性和环境的区别。API 返回或人工输入不自动等于已验证；缺失不是“加载失败”；不能为凑文案改后端枚举。

跨页保持商品、店铺、目标市场、流程/步骤及安全返回信息。当前 J0 使用 `productId` 等 query，其他链路可能使用不同命名；盘点后经集中适配兼容，不能全局搜索替换破坏旧深链。作用域以服务端鉴权为准，URL 参数不授予权限。

切 Workspace/Store 时清除不适用的选中对象、批量操作及缓存，丢弃迟到响应。所有异步按钮有加载与重复提交保护；超时先查结果，不能盲目重试可能已执行的动作。403 显示无权限，409 保留输入并重载合法动作，422 就地指出字段错误。

不新增未经设计的 AI 表/Agent，不修改迁移历史，不绕过 Orchestrator 与 Action 审批。本次业务链所需后端变更必须落实到服务、契约、数据和测试，控制范围但不能以“只改前端”为由拒绝补齐；外部发送、发布、真实采购及主库操作不作为 UI 验收的默认授权。

### G. 执行分批与停止条件

**完成口径：前端真实操作 → 后端鉴权和业务校验 → 正确持久化/计算 → API 读回 → 刷新或重新登录状态一致 → 后续业务能继续。** 只完成 DOM、按钮响应、前端 mock、接口返回 200 或构建通过均不算闭环。

#### G.1 后端责任与缺口分类

| 类型 | 开发要求 | 能否标记完成 |
|---|---|---|
| 已有后端能力 | 核对真实 DTO、权限和异常契约，接通前端并补回归验证 | 端到端验证后可以 |
| 内部缺接口/字段/聚合/关联 | 设计并实现最小服务端扩展、持久化和测试，同批接入前端 | 仅列缺口或禁用按钮不可以 |
| 真实业务资料缺失 | 提供录入/导入/核验与保存路径，缺值明确为未知，补齐后能推进流程 | 能力可验收，数据完成度另列 |
| 外部平台权限/真实数据源缺失 | 内部请求、能力检测、授权状态、错误/等待/回执路径实现；隔离环境做契约测试，外部实网验收单列 | 只能声明内部完成，不能声明实网成功 |
| 业务规则存在实质歧义 | 问具体缺项并继续无关工作；不要发明费用率、审批人、核验标准或市场需求 | 待决定部分保持未完成 |

不要把“待接入”用在我们自己还没写的 CRUD、画像保存、报价录入、费用完整性、订单聚合或作用域校验上。占位和临时 mock 只能用于施工，验收版本必须移除业务假数据回退。外部 API 的联调替身仅在显式测试环境使用，测试输出不得进入生产业务事实。

#### G.3 每项功能的接口契约卡

在编码前为本批实际动作填写契约卡，并把结果维护到 `docs/CONTRACT.md` 或其明确引用的唯一来源；不要只维护前端自己的接口假设：

- 页面/用户任务、输入对象及关联 ID、既有或新增的路由与方法。
- 请求字段、类型、必填/可空、默认含义、币种/单位、日期与分页/筛选范围。
- 响应字段、来源、核验/完整性、更新时间、合法下一步；不存在的字段不能让前端猜测。
- 租户/Workspace/店铺归属、可访问角色、操作权限；服务器核验所有传入关联 ID，不能信任客户端 workspace_id。
- 当前状态、允许的状态转移、事务边界、重复提交语义、并发冲突处理；有版本控制时使用实际版本契约。
- 错误与恢复：沿用现有 401/403/404/409/422 契约和防信息泄露策略，记录重试条件；不强迫所有失败用一种状态码。
- 写入位置、读回方式、审计/关联标识以及真实测试数据和断言。

不要求每个查询都新建 BFF；先复用既有服务。有跨域聚合需求时用只读服务/BFF，业务写入仍交给对应领域。价格、利润、动作权限和状态判定不得在前后端各维护一套相互漂移的事实。

#### G.4 数据库与可靠性要求

- 先找现有表/配置结构是否足以承接，不能为每张原型建新表，也不能把不同业务事实塞进无边界 JSON 来逃避设计。
- 确需结构变更时新增 Alembic 迁移，禁止修改已执行迁移；实现 downgrade，回填幂等并有断言，新增 tenant_id 外键按项目规范声明。
- 在隔离测试库验证升级、回填、约束和回滚；按规范执行 migration_preflight。主库迁移不随页面验收自动执行，若明确授权操作主库，执行前冷备且 P0 清零。
- 关键关联必须有可验证归属与唯一性，不能跨空间拼装 Product、Store、Offer、Order。事务失败不能留下“界面成功但部分数据缺失”的半成品。
- 对财务金额、汇率与舍入遵守现有精度规范，不由前端 Number 运算替代服务端核算；缺值与合法零值区别保存和返回。
- 对业务写入按真实风险实现防重复、并发冲突与审计。异步请求返回任务身份，前端查询真实结果，不在接受请求时显示执行成功。
- 数据量稍大时验证聚合和列表分页范围，不按当前页统计全量指标，不引入逐行串行请求或明显 N+1 查询。

#### G.5 每批交付必须是纵向切片

顺序为：契约与用例 → 必要迁移/服务/API → 后端测试 → 前端真实接口接入 → 浏览器交互与重新读回 → 异常/权限/回归 → 文档。禁止先写十个前端占位页再把后端工作全部推到后续。

至少保存一项写操作的完整证据：使用隔离数据在真实页面保存，记录对应请求和脱敏响应，通过新的 GET 或隔离库断言核实落库，再刷新页面验证显示，并从该对象进入下个业务步骤。只用同一个响应更新前端内存不是读回验证。

接口/单元测试可以使用 fixtures；最终内部功能验收必须由真实 FastAPI + 隔离数据库承接，不可全程拦截请求返回假成功。真实外部结果与适配器测试结果分别记录。

按本文件第四节执行：B0 复核 → B1 正确性与外壳 → B2 起步与研究 → B3 商品与供给 → B4 上线与 AI → B5 费用与订单 → B6 综合验收。

每批只改本批所需文件；完成功能后立即做有针对性的测试和实际页面验证，不把十页全部写完才检查。不能因缺一个外部接口停掉独立可完成页面，但该动作必须记为未接入，不能计为完成。

若缺少影响业务正确性的决定、身份或外部授权，只询问具体缺项并继续独立工作。没有真实浏览器/服务环境时保留静态成果，明确缺少的视觉和运行证据，不宣布“全站已完成”。

### H. 验收与交付

- 视觉：逐页记录原型编号、实际路由、构建、角色、数据环境、视口、系统真实截图。分别比较导航、区块顺序、密度、字体、色彩、主动作、状态及响应式。推导页面单列，不冒称原型还原。
- 业务：验证无资源/有商品或工厂/已有店铺三条起步路径；商品→货源→费用→目标店铺→上线→素材→返回任务不需复制 ID。订单另验采购/履约/结算真实关联。
- 后端闭环：每页展示字段有来源、每个可用写按钮有真实接口；保存/审批/执行后的新请求读回、刷新/重登、下一业务步骤和审计可追踪。内部缺口未实现必须列未完成，不能划成外部依赖。
- 数据：多币种、多店铺、零数据、缺费用、部分源失败、外部等待；不能把缺数据变零或全部成功。
- 权限：OWNER、OPERATOR、READ_ONLY、COMPLIANCE、PLATFORM_ADMIN、FACTORY_COLLABORATOR 分别验证允许入口和禁止动作；后端权限矩阵仍是依据。
- 测试：修改处的交互/契约/状态测试有真实断言，随后执行 `frontend-v9` 测试和构建；后端有改动按项目要求执行 pytest、ruff、权限/迁移相关检查。项目要求的全量/反序门禁不能用前端构建替代。可运行/可部署结论需隔离 E2E；构建链路、容器/TLS 改动按项目规范追加检查，不为 UI 顺手改部署。
- 文档：更新涉及的设计决策、API 契约、进度和文档地图；截图生成物先配置忽略策略。提交前 dry-run 核对，只提交本批自有变更，保留旧版回退。
- 每批交付：完成页面与行为、改动文件、检查结果与截图证据、未完成接口/风险、下一批；最终区分“视觉已对齐”“业务已验证”“外部能力未接入”。不要只汇报测试通过和完成百分比。

现在先执行 B0 的只读复核，形成精简映射和风险说明，然后进入已授权批次；不要未经验证宣称当前运行系统与原型一致。
