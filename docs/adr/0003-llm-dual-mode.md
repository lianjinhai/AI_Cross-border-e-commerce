# ADR-0003：LLM 双模架构

- **状态**：Accepted
- **决策编号**：[`DECISIONS.md` D3](../DECISIONS.md#L27)
- **日期**：项目初期（早于 2026-09-23）

## Context

平台定位是「AI 原生经营操作系统」，但存在两个硬约束：

1. **演示环境零配置必须可跑通全部流程**——不能因为没配 API Key 就让产品不可用；
2. **LLM 是外部依赖**，会超时、限流、返回不合法 JSON、被供应商下线。

若把 LLM 当作唯一执行路径，产品可用性就完全绑在外部服务上；若只写规则引擎，
则「AI 原生」名不副实，且后续接大模型要重写全部 Agent。

## Decision

每个 Agent 方法**统一走同一入口** `ask_json(prompt, fallback)`：

- **配置了 API Key** → 调 Model Router（OpenAI 兼容协议，默认智谱 GLM）要求 JSON 输出，
  带容错解析；
- **未配置 / 调用失败 / 输出不合法** → 无缝降级到**确定性规则引擎**。

两条路径**必须输出同构的字段**，契约固化在 `docs/CONTRACT.md`。

## Consequences

**收益**

- 演示环境零配置即可跑通全流程；
- 生产接入大模型后，**同一套代码自动升级**为 AI 生成/分析，无需改 Agent；
- LLM 故障**不阻塞业务**——降级路径始终可用。

**代价**

- 规则引擎需要与 LLM 输出**同构维护**：改字段要同时改两处，否则降级路径静默产出
  缺字段结果；
- 契约文档（`docs/CONTRACT.md`）成为强制同步项，属持续成本。

**衍生约束**

- 输出字段变更必须同步 `docs/CONTRACT.md`（规范 §10 Doc-4）；
- 「`in ("rule","llm")`」这类断言**属恒真断言**——它无法区分两条路径的行为差异，
  不得用作正确性守护（见 `DECISIONS.md` D14 / D16）。

## Alternatives considered

| 方案 | 否决理由 |
|---|---|
| **只做 LLM，无规则引擎** | 演示环境不可用；LLM 故障即业务中断；测试无法确定性断言 |
| **只做规则引擎** | 与「AI 原生」定位不符；后续接大模型需重写全部 Agent |
| **在 Agent 内各自判断是否可用 LLM** | 判断逻辑分散，必然出现「部分 Agent 有降级、部分没有」的不一致 |
