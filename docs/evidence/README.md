# 界面佐证 · 总索引与对照说明

> 本目录存放各批次验收时的**真实浏览器截图**与配套判定报告。
> 用途只有一个：**领到任务的人能对照「做到什么程度算对」**。
> 本目录是**权威副本**；项目网盘「界面佐证」为镜像（同一文件名、同一序号）。

---

## 一、怎么用（领任务后 4 步）

1. 先读任务描述里指定的**截图清单**——每个子项都写了具体文件名，不要凭感觉找。
2. 到对应批次目录里找同名截图，对照四件事：布局、字段、文案、状态标签。
3. 再打开同目录的判定报告（`REPORT.md` / `VERDICT.md` / `ROUND2_CONCLUSION.md`），核对**判定标准**：报告里的「门槛逐条判定表」每行都指向具体证据，不是主观描述。
4. 自己交付时按同样命名、同样场景补图。**缺一张即视为未完成**，不接受「大致做了」。

## 三、看图时的三条判据

1. **宽度看断点**：文件名末尾的 `1440` / `768` / `390` 是**视口宽度**，不是图片像素尺寸。桌面看 1440、平板看 768、移动看 390，三者都要不溢出、不截断。
2. **必须存在失败态**：空态、无权限、加载失败、未接入——只展示成功画面的截图**不算通过**。
3. **禁词红线**：`WAITING_EXTERNAL`（等待外部回执）的画面里**不得出现「已上线 / 发布成功」**；`settlements` 是供应商应付对账，**不得**当成 GMV 或平台回款。

---

## 四、新增截图时的硬要求

1. **真机拍，不用 mock**：隔离副本库 + 真 uvicorn + 真实浏览器；禁止拿演示种子数据冒充真实结果。
2. **命名**：`<序号>-<场景>-<宽度>.png`，与本目录既有文件同名同序，便于跨批次比对。
3. **双位置存放**：仓库 `docs/evidence/<批次>/`（权威）+ 项目网盘「界面佐证/<批次>/」（镜像）。**只存仓库不算交付**，两处必须一致。
4. **画面要能读出关键字段**：数据来源标签（demo / api / local / rule / llm）、币种符号、状态文案。
5. **视觉变更**：同一角色、同一数据下，「改前 / 改后」各一张。

---

## 五、新批次接入方式

1. 新建 `docs/evidence/<批次名>/`，按上表格式在本文件「批次总览」补一行。
2. 报告文件名遵循既有惯例：批次级用 `REPORT.md`，验收级用 `VERDICT.md`，QA 轮次用 `ROUND2_CONCLUSION.md`。
3. 提交前跑 `backend/scripts/check_docs_consistency.py --json`，要求 `total=0`。
