## 一、八条业务流程（A–H）

### 旅程 A · 新手启动
**目标**：从零到「商品开始上线」的全引导路径。
**步骤**：注册登录 → 选经营目标 → 能力画像 → 经营路径 → 找货源 → 连店铺 → 选商品 → 开始上线。

| 环节 | 页面 | 关键操作 | 现状 |
|---|---|---|---|
| 注册登录 | `/login` | 登录 | ✅ 有；但**无注册**、写死演示账号 |
| 选经营目标 / 能力画像 / 经营路径 | —（无页面） | 选择目标与画像 | ⛔ **断点1：无注册页，无「经营目标/能力画像/经营路径」任何页面**（Context 有 `capability_profile`/`business_stage` 字段，无 UI） |
| 找货源 | `/discovery`、`/suppliers` | 看趋势/机会、看供应商 | ✅ 有（但无引导串联） |
| 连店铺 | `/shops` | 添加授权店铺 | ✅ 有 |
| 选商品 | `/products` | 采集/新增商品 | ✅ 有（结果不自动流向下一步） |
| 开始上线 | `/listings` 或 `/launch` | 生成 Listing / 创建上线流程 | ⛔ **断点2：`/launch` 无「创建上线流程」入口**（后端 `POST /launch` 已存在，前端未封装） |
| 上线完成 | `/launch/:id` | 提交平台→（平台反馈）→核验在售 | ⛔ **断点3：真实「在售核验」未实现**，Listings 发布止于 SUBMITTED/待核验 |

- **完成标准**：商品在目标平台**在售**（`platform_status=ACTIVE` 且 `verification_status=VERIFIED`）。**当前不可达**。
- **返回路径**：无引导式回链。
- 🔧 期望链路：`/login` → **首用引导向导（新页面，3 步：目标/画像/路径）** → 引导式「下一步」直达 `/shops→/products→/launch` → 上线成功后引导回首页「今日经营」并展示进度。

### 旅程 B · 有工厂用户
**目标**：把自有/合作工厂的 SKU 变成海外机会并上线。
**步骤**：Workspace → 维护工厂 SKU → 海外机会 → 目标市场 → 创建 Listing → 进入上线中心。

| 环节 | 页面 | 关键操作 | 现状 |
|---|---|---|---|
| 维护工厂 SKU | `/factory-portal` | 新增/更新工厂产品 | ✅ 有（仅目录） |
| 海外机会 | `/suppliers` | 市场机会 × 私域工厂匹配 → 转报价 | ✅ 有（`/factory-network/opportunities/match`） |
| 目标市场 | —（无独立视图） | 选目标国家/履约方式 | ⛔ **断点：无独立「目标市场」页面**（仅散在 `/shops` 店铺 commerce 字段） |
| 创建 Listing | `/listings` | AI 生成 Listing | ✅ 有 |
| 进上线中心 | `/launch` | 创建上线流程 | ⛔ **断点：`/launch` 无创建入口** |

- ⚠ **前提校正**：本旅程**把「工厂账号」与「ERP 运营」混为一人**。工厂账号受守卫强制只能进 `/factory-portal`（`permissions.js` 的 `routeRedirect`→`FACTORY_COLLABORATOR` 分支），无法执行机会/目标市场/创建 Listing。真实是两段协作：工厂（G）维护 SKU ↔ ERP 运营（B/E）做机会/Lising/上线。
- **完成标准**：工厂 SKU 经 Listing 复核 + 人工审批后进入上线中心并提交平台。
- **返回路径**：无（跨角色无回链）。
- 🔧 期望链路：工厂侧 `/factory-portal` 提交 SKU → ERP 侧在 `/shops`（销售渠道）内确定**目标市场** → `/suppliers` 匹配 → `/listings` 生成 → `/launch` 创建流程；上线中心详情对工厂投影「本厂指派步骤」（只读，不泄露卖家完整详情）。

### 旅程 C · 已有店铺卖家
**目标**：接已有店铺，用真实数据驱动优化。
**步骤**：连店铺 → 同步商品与订单 → 分析表现 → 查问题 → AI 建议 → 审核执行。

| 环节 | 页面 | 关键操作 | 现状 |
|---|---|---|---|
| 连店铺 | `/shops` | 添加/授权 | ✅ 有 |
| 同步订单 | `/orders` | `/shops/{id}/sync_orders` | ✅ 有 |
| 同步**商品** | —（无入口） | 从店铺拉商品 | ⛔ **断点1：无「从店铺同步商品」入口**（仅订单同步；商品靠采集/手动） |
| 分析表现 | `/products`详情 或 `/discovery/performance` | 看经营表现分 | ✅ 有 |
| 查问题 | `/alerts` | 风险巡检 | ✅ 有（缺处置跳转） |
| AI 建议 | `/ai-decisions`、AI 助手、`/bi` 报告 | 看建议与依据 | ✅ 有（分散） |
| 审核执行 | Listings `PublishActions` / Ads `/actions` / Launch actions | 审批并执行 | ⛔ **断点2：审批三套割裂**，无统一「待我审批」 |

- **完成标准**：真实数据回流（订单/表现分）→ 依 AI 建议完成一次优化动作并留审计。
- **返回路径**：无（跨页无回链）。
- 🔧 期望链路：`/shops` 一键「同步商品+订单」→ `/products` 表现分 → `/alerts` 告警卡片「去处理」 → 统一「待我审批」页（合并三套 actions）→ 结果回写首页。

### 旅程 D · 专业批量上新
**目标**：多商品 × 多店铺批量上线并追踪。
**步骤**：筛商品 → 多 Store → 批量上线任务 → 查问题 → 批量合法动作 → 追踪。

| 环节 | 页面 | 关键操作 | 现状 |
|---|---|---|---|
| 筛商品 | `/products` | 筛选 | ✅ 有 |
| 批量选择 | —（无多选） | 多选商品 | ⛔ **断点1：表格无多选列** |
| 创建批量上线 | `/launch` | 批量创建流程 | ⛔ **断点2：无创建入口 + 动作是单 run 步骤级，无批量动作** |
| 追踪 | `/launch` | 筛选追踪 | ⚠ 部分（筛选可用） |

- **完成标准**：N 商品 × M 店铺的批量上线任务建立并可持续追踪。
- **返回路径**：无。
- 🔧 期望链路：`/products` 多选 → 「批量上线」→ `/launch` 批量创建向导（选 Store/Profile）→ 列表按「需我处理/阻断」分组追踪 → 批量合法动作。
- **现状判定**：**该旅程当前基本不可用**。

### 旅程 E · 采购与履约
**目标**：订单驱动的采购—发货—物流—完成—财务核对闭环。
**步骤**：订单 → 货源匹配 → 采购 → 发货 → 物流 → 完成 → 财务核对。

| 环节 | 页面 | 关键操作 | 现状 |
|---|---|---|---|
| 订单 | `/orders` | 查看/同步订单 | ✅ 有 |
| 货源匹配 | —（订单页无入口） | 匹配货源/一键代发 | ⛔ **断点1：订单页无「货源匹配」入口**（代发在 `/products`、采购单在 `/suppliers`，反向无深链） |
| 采购 | `/suppliers`（采购单 tab） | 创建采购单/收货入库 | ✅ 有 |
| 发货 | `/orders` | 发货（生成 tracking_no） | ✅ 有 |
| 物流 | —（无页面） | 跟踪物流 | ⛔ **断点2：无物流跟踪页** |
| 完成 | `/orders` | 状态→delivered | ✅ 有 |
| 财务核对 | `/finance` | 核对订单行/费用 | ⚠ 有，但**断点3：手输订单 ID** |

- **完成标准**：订单全链状态一致（paid→shipped→delivered）+ 采购入库 + 财务口径对齐。
- **返回路径**：无。
- 🔧 期望链路：`/orders` 行内「货源匹配」→ `/suppliers` 采购 → 发货后行内可展开物流 → `/finance` 由订单直接带 `order_id` 跳转。

### 旅程 F · 合规审批
**目标**：合规员高效审批待上架 Listing。
**步骤**：待审核 → 看商品与目标市场 → 看风险与证据 → 审批 → 返回原任务。

| 环节 | 页面 | 关键操作 | 现状 |
|---|---|---|---|
| 待审核 | `/compliance-workbench` | 看队列 | ✅ 有 |
| 商品/目标市场/证据 | —（上下文不足） | 核对 | ⛔ **断点1：队列仅有 标题/平台/原因，缺商品详情/目标市场/风险证据链** |
| 审批 | 同上 | 放行/驳回 | ✅ 有 |
| 返回原任务 | —（无回链） | 回到审批前位置 | ⛔ **断点2：无「返回原任务」**（若入口来自 `/listings` 复核弹窗，结束只关弹窗，无 return_to） |

- **完成标准**：待审批队列清零，放行项内容/规则版本一致，审计留痕。
- **返回路径**：⛔ 无。
- 🔧 期望链路：工作台队列行 → 侧滑「商品 + 目标市场 + 风险证据 + 版本」→ 审批 → 自动回队列并定位下一项；从 `/listings` 进入的审批带 `return_to` 回原行。

### 旅程 G · 工厂协作
**目标**：外部工厂伙伴接收并完成 ERP 指派的任务。
**步骤**：收到备货/报价任务 → 看 SKU → 提交数据材料 → 完成。

| 环节 | 页面 | 关键操作 | 现状 |
|---|---|---|---|
| 收到任务 | —（无收件箱） | 查看被指派任务 | ⛔ **整条旅程缺失** |
| 看 SKU | `/factory-portal` | 查看本厂 SKU | ✅ 仅有目录 |
| 提交材料 | —（无入口） | 提交数据/材料 | ⛔ 缺 |
| 完成 | —（无入口） | 标记完成 | ⛔ 缺 |

- **说明**：`/factory-portal` 目前**只有「本厂供给目录」维护**，无任务/收件箱/被指派任务视图；`docs/LAUNCH_CENTER_PRODUCT_DESIGN.md §6` 设计的「Factory 通过既有门户看本厂指派步骤」**未实现**。
- **完成标准**：工厂完成被指派的备货/报价步骤并回执，ERP 侧可见。
- **返回路径**：无。
- 🔧 期望链路：`/factory-portal` 顶部「我的任务」收件箱（备货/报价/资料）→ 任务详情（SKU + 要求 + 缺项）→ 提交材料 → 标记完成 → 上线中心对应步骤变为 READY/COMPLETED。

### 旅程 H · AI 经营优化
**目标**：真实数据 → 异常/机会 → AI 建议 → 证据审查 → 审批执行 → 结果记录（可追溯闭环）。
**步骤**：真实数据 → 异常/机会 → AI 建议 → 证据审查 → 审批执行 → 结果记录。

| 环节 | 页面 | 关键操作 | 现状 |
|---|---|---|---|
| 真实数据 | `/bi`（metrics + data-quality） | 看经营口径 | ✅ 有 |
| 异常/机会 | `/alerts`、`/discovery` | 巡检/机会发现 | ✅ 有（Alerts 缺处置跳转） |
| AI 建议 | AI 助手 / `/bi` 报告 / `/ai-decisions` | 获取建议 | ✅ 有（分散） |
| 证据审查 | `/ai-decisions` 详情 | 看依据链 | ✅ 有 |
| 审批执行 | 三套 actions | 审批并执行 | ⛔ **断点：审批执行不统一** |
| 结果记录 | `/workflows` 运行历史 + `/ai-decisions` | 复盘 | ✅ 有（分散） |

- **完成标准**：一次「建议→执行→结果」全程可追溯（`/ai-decisions` 有证据，`/workflows` 有运行，审批有审计）。
- **返回路径**：无统一视图（链路分散在 5 个页面）。
- 🔧 期望链路：统一的「建议→证据→审批→结果」视图（合并三套审批 + AI 日志三处），首页「今日经营」聚合「AI 完成了什么 / 哪些异常」。

## 二、七类用户画像（A–G）

> 每类给：起点 → 经过页面 → 关键操作 → 完成标准 → 返回路径；标注断点与期望链路。

### 画像 A · 无跨境经验的个人
- **起点**：`/login`（登录后应进入引导，现状直接落 `/dashboard`）。
- **经过页面**：`/login` →（⛔ 缺引导页）→ `/discovery` → `/shops` → `/products` → `/listings`/`/launch`。
- **关键操作**：选目标/画像 → 连店 → 选品 → 上线。
- **完成标准**：首个商品在售。
- **返回路径**：无。
- **断点**：⛔ 无经营目标/能力画像/经营路径页（G1）；⛔ `/launch` 无创建入口（G2）；⛔ 首页对新手门槛过高（G6）。
- 🔧 **期望链路**：登录 → 3 步首用向导 → 引导式「下一步」按钮一路带到上线成功 → 首页展示「你的第一个商品已上线」。

### 画像 B · 有 1688 货源或采购经验
- **起点**：`/products`（采集 1688）或 `/discovery`（选品）。
- **经过页面**：`/discovery` → `/products` → `/suppliers` → `/shops` → `/listings` → `/launch`。
- **关键操作**：采集/代发下单 → 供应商/报价 → 上架。
- **完成标准**：货源商品完成上架并进入履约。
- **返回路径**：无。
- **断点**：⛔ 选品结果无下一步跳转（G，见 Discovery 问题）；⛔ `/launch` 无创建入口（G2）；⛔ 采购/履约断链（G7）。
- 🔧 **期望链路**：`/discovery` 选品 → 商品池 → 一键采购/代发 → 上架 → 采购与履约贯通。

### 画像 C · 自有或合作工厂
- **起点**：`/suppliers`（录入/尽调工厂）或 `/factory-portal`（工厂账号）。
- **经过页面**：`/suppliers` → `/factory-portal` → `/discovery` → `/products` → `/listings` → `/launch`。
- **关键操作**：工厂建档/尽调 → 匹配机会 → 转报价 → 生成 Listing → 上线。
- **完成标准**：工厂 SKU 经复核审批后上线。
- **返回路径**：无。
- **断点**：⛔ 无独立目标市场视图（G20）；⛔ 工厂协作任务缺失（G5）；⛔ `/launch` 无创建入口（G2）。
- 🔧 **期望链路**：工厂数据完整度看板 + 机会匹配结果 + 指定目标市场 → Listing → 上线中心（含工厂投影）。

### 画像 D · 已有跨境店铺的个人卖家
- **起点**：`/shops`（授权已有店铺）。
- **经过页面**：`/shops` → `/orders` → `/products` → `/alerts` → `/bi` → 审批（三套）。
- **关键操作**：授权 → 同步 → 分析 → 优化。
- **完成标准**：真实数据可用 + 完成一次数据驱动优化。
- **返回路径**：无。
- **断点**：⛔ 无店铺商品同步入口（G13）；⛔ 审批三套不统一（G8）；⛔ 履约链断裂（G7）。
- 🔧 **期望链路**：一次授权 → 商品+订单同步 → 表现分 → 统一「待我审批」→ 结果回首页。

### 画像 E · 专业跨境运营
- **起点**：`/launch`（上线中心）或 `/discovery`（批量选品）。
- **经过页面**：`/discovery` → `/products`（多选）→ `/launch` → `/launch/:id` → `/workflows`。
- **关键操作**：批量选品 → 多店铺创建上线 → 批量合法动作 → 追踪。
- **完成标准**：批量任务建立并闭环；领域动作可用。
- **返回路径**：详情→列表（`return_to` 部分可用，且仅 `/launch*`）。
- **断点**：⛔ 无批量选择（G16）；⛔ `/launch` 无创建入口（G2）；⛔ 领域动作 B03–B09 未接通（G3）；⛔ 深链白名单过窄（G14）。
- 🔧 **期望链路**：商品多选 → 批量创建向导 → 列表分组追踪 → 批量动作（GUIDED/PROFESSIONAL 同源可切换）。

### 画像 F · 多人团队 / 企业管理员
- **起点**：`/dashboard`（管理视角）或 `/settings`、`/users`。
- **经过页面**：`/dashboard` → `/users` → `/settings` → `/bi` → `/compliance-workbench`。
- **关键操作**：成员与角色维护 → 经营参数/LLM 配置 → 审计。
- **完成标准**：团队权限清晰、设置生效、审计可查。
- **返回路径**：无。
- **断点**：⛔ 首页无「成员/授权到期/审计/待人工审批」聚合（G6）；⛔ Users 角色枚举双轨（G18）；⛔ 设置范围溢出（G29 对应）。
- 🔧 **期望链路**：管理首页聚合（成员/授权/审计/待审批）+ 枚举对齐 + 设置拆分。

### 画像 G · 外部工厂协作者
- **起点**：`/factory-portal`（守卫强制，`permissions.js` 的 `routeRedirect`→`FACTORY_COLLABORATOR` 分支）。
- **经过页面**：`/factory-portal`（当前唯一）。
- **关键操作**：维护本厂 SKU（当前）；应含接收任务/提交材料。
- **完成标准**：完成被指派任务并回执。
- **返回路径**：无（独立域，无跨域回链）。
- **断点**：⛔ 无协作任务收件箱（G5，整条旅程缺失）。
- 🔧 **期望链路**：门户首页「我的任务」→ 任务详情（SKU/要求/缺项）→ 提交材料 → 完成 → ERP 侧步骤推进（工厂只见本厂数据）。
